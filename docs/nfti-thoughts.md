# NFTI 项目思考与想法

> 写于 2026-07-22 · 基于 v2.1-alpha 代码库分析

---

## 1. NFTI 的独特价值

### 1.1 不是 MBTI 复刻，而是校园文化编码

NFTI 最聪明的一点是重新编码了人格维度的命名体系，完全脱离心理学论文语言，变成学生听得懂的话：

| MBTI | NFTI | 含义 |
|---|---|---|
| E / I | **O**pen / **R**eserved | 敞开 / 内敛 |
| S / N | **G**athering / **V**ision | 务实 / 远见 |
| T / F | **L**ogic / **E**motion | 理性 / 共情 |
| J / P | **S**tructured / **F**lexible | 有序 / 灵活 |

题目场景全部来自南方中学真实生活——社团招新、校园跑、食堂、运动会。这让测试结果对使用者有「这是我的学校」的归属感，而不是「我是一个 INTP」这种抽象标签。

### 1.2 19 种人格 = 探索动机

16 种标准人格 + 3 种隐藏款。隐藏人格制造了天然的探索动机——学生会想「我要怎么才能测出隐藏款？」，相当于一个无需开发的成就系统。

### 1.3 QQ 频道社区闭环

测完 → 分享到频道 → 看别人结果 → AI 学长聊人格 → 再测。这个闭环是很多心理测试产品做几年才想明白的事，v1 就已有雏形。

## 2. 可优化的方向

### 2.1 测试结果缺乏横向对比

当前结果页是单人体验：你是什么人格 → 人格描述 → 插图。

如果能加频道内统计——「在南方中学频道里，OVES 占比 23%，是最多人的人格」「RGLF 只有 2%——你是稀有款」——会让结果更有社交分享的动力。`type_distribution` 数据已在 `stats` 接口中存在，只缺前端展示。

### 2.2 AI 学长的能力被低估了

当前 `aiChat.ts` 只是将人格类型拼入 system prompt 后调 DeepSeek。可以做更多：

- **跨人格对比**：「ISFJ 和 OVES 在社团选择上有什么不同？」
- **人格解读 + 校园建议**：「你是 OVES，适合文学社还是街舞社？」
- **生成分享文案**：「帮我把测试结果写成一段适合发频道的话」
- **记住历史对话**：结合 test_results 数据，越聊越懂用户

这些不需要改架构，只需优化 system prompt 和增加预设问题按钮。

### 2.3 新测评不应是独立功能，而是补充维度

大五人格和职业测评的方向很对，但要考虑它们与 NFTI 的关系：

| 维度 | NFTI | 大五 | 职业（霍兰德） |
|---|---|---|---|
| 身份感 | 强（南方中学专属） | 弱（通用） | 中 |
| 分享动力 | 高（「我是南方人」） | 低 | 中 |
| 复测频率 | 偶尔（人格稳定） | 偶尔 | 偶尔 |
| 组合价值 | — | 大五 × NFTI 交叉分析 | 职业 × NFTI 交叉分析 |

**建议**：不加成独立测评，而是做成**补充维度**。例如在 NFTI 结果页展示「你的大五开放性得分 85，与 OVES 人格高度相关」——这比单独一个大五结果页更有意义。

### 2.4 数据资产未被充分利用

`test_results` 表已有数据，但未挖掘：

- 频道里最受欢迎的人格分布？
- 快速测试与完整测试的结果一致性？
- 某些题目回答与最终人格的相关性（题目质量分析）？

这些数据可做成**频道周报**或**趣味统计**（「本周 NFTI 人格分布」），本身就是内容，可定期发布维持频道活跃度。

## 3. 长期产品设想

```
NFTI 2.0 方向
├── 测评中心
│   ├── NFTI（现有）
│   ├── 大五人格（补充维度）
│   ├── 职业兴趣（补充维度）
│   └── 交叉分析报告
├── 人格广场
│   ├── 按人格分类的讨论区
│   ├── 跨人格辩论/话题
│   └── 人格排行榜 / 稀有度展示
├── AI 学长 2.0
│   ├── 记住人格 + 历史对话
│   ├── 跨人格对比分析
│   └── 生成分享内容
├── 校园人格地图
│   └── 每个人格标注「你在校园里会出现在哪」
└── 每周人格挑战
    └── 基于人格类型的校园任务
```

## 4. 技术架构建议（增量路线）

| 阶段 | 内容 | 影响范围 |
|---|---|---|
| Phase 0 | 修复现有 bug（已完成） | backend |
| Phase 1 | 抽象测评引擎 + registry | TestView, store, router |
| Phase 2 | 数据库加 `assessment_type` 字段 | backend `db.mysql.js` |
| Phase 3 | 大五人格数据 + 结果组件 | 新增文件 |
| Phase 4 | 主页入口 + 个人中心分组改造 | HomeView, ProfilePage |
| Phase 5 | 社交强化（分布统计、分享文案） | ResultView, AI chat |

---

## 5. 总结

NFTI 的核心优势是**人格 × 校园文化 × 社交**这个三角定位，不是技术。技术上的 bug（MySQL datetime、proxy.js 跨平台）是成长痛，修了就好。

建议的优先级：

1. **先把 NFTI 本身的社交闭环做透**——让结果更好看、更好分享、更有话题性
2. **再以补充维度形式加入新测评**——让 NFTI 更立体，而非分散注意力
3. **数据驱动迭代**——利用已有数据做内容，维持社区活跃度
