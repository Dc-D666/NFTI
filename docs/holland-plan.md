## 一、概述

### 1.1 目标

在现有 NFTI 人格测试的基础上，新增霍兰德职业兴趣测评（RIASEC），形成「人格 × 职业」双测评体系。

### 1.2 设计原则

| 原则 | 说明 |
|------|------|
| **不改现有 NFTI 代码** | 所有 NFTI 已有功能零影响 |
| **独立完整可分享** | 不测 NFTI 也能获得完整体验 |
| **交叉是增值而非门槛** | 两套都测了的用户获得额外洞察 |
| **校园特色翻译** | 六种类型映射为南方中学角色 |

### 1.3 与频道的关系

霍兰德天然适合南方中学频道场景：

| 频道痛点 | 霍兰德的解法 |
|----------|-------------|
| 学习版块内容偏少 | 职业测评结果 = 高质量可讨论内容，可沉淀到学习版块 |
| 毕业生 950 人（最大群体） | 验证代码准确性（「我学这个专业，测出来果然是 I」） |
| 高一 750 人 / 高二 700 人 | 刚需窗口期——选科、选专业、思考未来方向 |
| 📚学习版块内容偏少 | 测评结果可成为学习版块的讨论话题 |
| 吐槽/求助版块活跃但无沉淀 | 职业讨论是有信息量的话题，能拉升频道调性 |

### 1.4 频道真实情况（基于频道知识库）

| 特征 | 数据 |
|------|------|
| 频道名 | 南方中学频道（高考加油💪）|
| 成员数 | 3035 人 |
| 毕业生 | 950 人（31%，最大群体） |
| 在校生 | 高一 750 / 高二 700 / 高三 400 |
| 日活 | 工作日 ~300 人 / 周末 ~900 人 |
| 老师 | 3 位（团委/学生科），日均访问 7/5.5/2 次 |
| 高频版块 | 吐槽 > 求助 > 娱乐 > 学习 > 摄影 |
| 频道定位 | 半官方，半盈利（广告费 ~100-400 元/月全作为福利） |
| 运营模式 | 频道主一人承担绝大部分运营 |

**南方中学学生关心什么？**
- 学习资料、选科策略、分班考（学习版块有需求但内容不足）
- 高考、大学、未来方向（950 名毕业生已在大学，可做活验证）
- 社团活动（文学社、街舞社、生物社、商帮、动漫社、话剧社等活跃）
- 日常吐槽和求助（高频但无沉淀价值）

对霍兰德测评的意义：学生既有「我以后干什么」的求知欲，又有毕业生群体做验证，还有社团场景作为题目素材。

## 二、数据模型

### 2.1 数据库变更

**表 `test_results` 改两处：**

① `db.mysql.js` 中 `SCHEMA` 的 `CREATE TABLE`（新装时生效）：

```sql
CREATE TABLE IF NOT EXISTS test_results (
  ...
  assessment_type VARCHAR(32) NOT NULL DEFAULT 'nfti',
  mode ENUM('quick','full','debug','holland') NOT NULL DEFAULT 'full',
  ...
)
```

② 已有数据库执行 ALTER（现有 NFTI 数据不受影响）：

```sql
ALTER TABLE test_results ADD COLUMN assessment_type VARCHAR(32) NOT NULL DEFAULT 'nfti';
ALTER TABLE test_results MODIFY COLUMN mode ENUM('quick','full','debug','holland') NOT NULL DEFAULT 'full';
```

同时 `db.mysql.js` 的 `saveTestResult` 需要将 `params.assessment_type` 写入。

### 2.2 前端类型（新增 `types/holland.ts`）

```typescript
// 霍兰德六种维度
export type HollandDimension = 'R' | 'I' | 'A' | 'S' | 'E' | 'C'

// 每题配置
export interface HollandQuestion {
  id: number
  text: string            // 题目文本（已翻译为校园场景）
  dimension: HollandDimension
}

// 计分结果
export interface HollandScores {
  R: number
  I: number
  A: number
  S: number
  E: number
  C: number
}

// 完整结果
export interface HollandResult {
  code: string            // 三位代码，如 "SIA"
  primary: HollandDimension
  secondary: HollandDimension
  tertiary: HollandDimension
  scores: HollandScores
  roleNames: [string, string, string]  // 校园角色名
  summary: string          // 一句话总结
}
```

### 2.3 现有类型扩展

```typescript
// TestResult 增加 assessment_type
export interface TestResult {
  assessmentType: 'nfti' | 'holland'
  mode: TestMode          // NFTI 用 quick/full/debug；霍兰德统一用 'full'
  type: PersonalityType | HollandResult
  scores: DimensionScores | HollandScores
}
```

## 三、题目与计分

### 3.1 题库结构

标准霍兰德自我探索问卷 42 题（每维度 7 题），全部翻译为南方中学场景。

**六类题目示例（所有场景均取自南方中学真实校园生活）：**

| 维度 | 校园版名称 | 题目示例（每题 5 题示意） |
|------|-----------|--------------------------|
| R（实干型） | 🔧 工匠 | 「机器人社要组装参赛机器，我宁愿动手焊电路也不愿写方案书。」<br>「比起做 PPT，我更喜欢亲手修好教室那扇总是卡住的柜门。」<br>「体育课自由活动，如果可以选择，我更愿意打球而不是坐着聊天。」<br>「生物社外出采集标本时，我是那个主动拿工具、负责搬运的人。」<br>「帮同桌修好了一只断掉的耳机，我比考了高分还开心。」 |
| I（研究型） | 🔬 学霸 | 「生物社做实验时，我会主动记录数据、分析误差、写实验报告。」<br>「月考出分后，比起分数本身，我更想知道这道题到底为什么错了。」<br>「频道里有人问学习方法，我会认真分析然后写一篇长回复。」<br>「我有一本自己的错题本，不为了给谁看，只是为了自己想清楚。」<br>「自习课上，比起和同桌聊天，我更愿意一个人安安静静钻研难题。」 |
| A（艺术型） | 🎨 文青 | 「文学社征稿，比起写议论文，我更愿意写小说或诗歌。」<br>「路过走廊的黑板报，我会忍不住想「如果我来设计会是什么样」。」<br>「摄影版块的活动我会想参加——不是为了获奖，是单纯喜欢拍。」<br>「音乐课自由展示环节，我会主动上去唱一首或弹一段。」<br>「看到好看的晚霞，我的第一反应是拍下来然后配一句话发频道。」 |
| S（社会型） | 🤝 暖叔/暖姐 | 「社团招新时，我会主动和路过的同学介绍社团、拉人入伙。」<br>「同桌心情不好，我会主动问TA怎么了，而不是假装没注意到。」<br>「频道里有人求助，我知道的话会回复，不知道也会帮TA @别人。」<br>「答疑学长团的活动，如果有机会我愿意报名参加。」<br>「分班后我是那个最先认识新同学的人。」 |
| E（企业型） | 💼 老板 | 「商帮在运动会上摆摊，我会主动负责推销和收款。」<br>「班级活动需要有人组织，我会站出来分配任务。」<br>「我擅长说服别人接受我的想法——不是强迫，是那种让人听了觉得「你说得对」的方式。」<br>「如果要为频道拉赞助，我觉得我可以谈下来。」<br>「社团竞选时，比起被选上，我更享受在台上演讲的那个过程。」 |
| C（事务型） | 📋 管家 | 「社团的经费流水，我会用 Excel 记得清清楚楚。」<br>「班级收班费时，我是那个负责记账、公示、催缴的人。」<br>「我的书桌和抽屉永远整整齐齐，每样东西都有固定位置。」<br>「考试前我会列一个复习计划表，然后一条条打勾完成。」<br>「频道里发活动通知，我会注意到排版和格式有没有对齐。」 |

**计分方式：** Likert 5 点量表（非常不同意 1 → 非常同意 5），每维度求和，取最高三位的首字母作为 Holland 代码。同分时按 R→I→A→S→E→C 优先级排序。

## 五、交叉分析（霍兰德 × NFTI）

### 5.1 映射逻辑

两者是互补关系而非一一对应——NFTI 描述「你是谁」（特质），霍兰德描述「你想做什么」（兴趣）。但存在常见组合倾向：

| NFTI 类型 | 常见霍兰德代码 | 交叉解读 |
|-----------|--------------|---------|
| OVES（南方氛围组） | SEA / ESA | 社交型 × 企业型——社团招新门面、活动策划 |
| OGES（奶茶团宠） | SAE / ASE | 社会型 × 艺术型——文学社、答疑学长团 |
| RVLS（南中战略家） | ICR / IRC | 研究型 × 事务型——竞赛、数据分析 |
| OGLS（班主任） | CER / CRE | 事务型 × 企业型——社团管理、组织协调 |
| RVEF（南中梦想家） | AIS / IAS | 艺术型 × 研究型——文学社写作、摄影 |
| JIAHAO（南方嘉豪） | EAS / ESA | 企业型 × 艺术型——商帮、活动策划 |
| GENIUS（985er） | IC / IRC | 研究型 × 事务型——竞赛、刷题、笔记 |
| DORM（宿舍长） | SCA / SAC | 社会型 × 事务型——班干部、社团后勤 |
| BANDIT（土匪头子） | ERI / EIR | 企业型 × 研究型——谈判、搞事情、钻规则漏洞 |
| WEEKLY（新闻周刊） | AIS / IAS | 艺术型 × 研究型 × 社会型——内容创作、频道运营 |

### 5.2 交叉结果展示

在霍兰德结果页底部，或 NFTI 结果页底部，或两者都有的情况下在个人中心展示：

```
你的 NFTI × 霍兰德交叉画像

OVES（南方氛围组）+ SIA（暖叔+学霸+文青）

你在社团里最适合的定位：
招新时的「门面担当」——O 让你自来熟，
S 让你照顾到每个人的感受，
A 让你能把招新海报做得很吸引人。

推荐尝试：社团外联、活动策划、招新宣传
```

### 5.3 交叉触发条件

- 仅当同一 `tiny_id` 下同时存在 `assessment_type='nfti'` 和 `assessment_type='holland'` 的记录时显示
- 没有任何强制——只测一套的用户看不到交叉内容

## 八、风险与应对

| 风险 | 概率 | 影响 | 应对 |
|------|------|------|------|
| 霍兰德代码与 NFTI 人格无显著关联，交叉分析显得牵强 | 中 | 中 | 交叉分析从「强关联」降级为「常见组合参考」，加上免责说明 |
| 42 题对寄宿生来说可能一次做不完 | 中 | 低 | 支持中途保存（localStorage 自动存进度），下次进来继续 |
| 结果页 NFTI 耦合太深，复用困难 | 低 | 中 | 独立视图组件而非共用；不强行合并 |
| 数据库改表影响现有数据 | 低 | 低 | `ALTER` 加默认值，不影响已有行 |
| 测评结果缺乏专业常模对照 | 中 | 中 | 初期只显示原始分数和相对高低，不宣称能预测职业成功。后续积累用户数据后可生成频道内常模 |
